2. **Typed Swift client from packages/api/openapi.json.** Prefer Apple's swift-openapi-generator (SPM plugin) so the client is generated, not hand-written, mirroring ADR 0007. 3. **Auth for iOS.** Passkeys on iOS need an associated domain over HTTPS, which does not exist yet, so decide and document (ADR) the bootstrap: the recommended path is Better Auth's `bearer` plugin on the server (token returned in a response header after sign-in, sent as `Authorization: Bearer` afterwards, stored in the Keychain) with sign-in via the existing magic link opened from the app (custom URL scheme or universal-link-shaped path handled by the app in the simulator) or a short-lived pairing code endpoint. The server's `Authorization` middleware (apps/server/src/auth/authorization.ts) currently reads only the cookie; extend it to accept a bearer token as well, with tests, and keep cookies working for the web. Add an `auth` section to the iOS README describing the first-run flow. Keep the "no sign-up, single user, runtime user creation blocked" invariant (ADR 0003).

4. **Chat on iOS.** Main-thread view with streamed replies (incremental `text_delta`, tool parts rendered as quiet "used create_task" lines, `message_end` replacing the bubble, `error` shown calmly), composer, the thinking flower while streaming. Verify against the running server with the real model at least once and record the trace id from Jaeger in the report.

5. **Tasks on iOS.** Task list (open statuses), done action, refresh on `tasks_changed`. Match apps/web's behaviour.
